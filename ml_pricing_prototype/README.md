\# ML Pricing Prototype - FUTURE SCOPE / NOT PART OF ACTUAL SUBMISSION



\## Important: what this is and isn't



This folder is a \*\*standalone prototype\*\* demonstrating what a fully trained

machine learning pricing model would look like, IF real historical sales data

existed. It is completely separate from the actual SIH submission.



\*\*The actual, working Team 5 pricing system is in `../ai\_engine/`\*\* - a

hybrid rule-based + Gemini AI pricing engine that works today, honestly,

without needing any historical data.



\## Why this exists



Our SIH problem statement is a brand-new platform - no artisan has sold

anything through it yet, so no real historical pricing data exists. Rather

than fabricate this data and pretend it's real (which would be dishonest),

we built this SEPARATE prototype using clearly-labeled SYNTHETIC data to:



1\. Demonstrate we understand the full ML pipeline (dataset design, cleaning,

&#x20;  feature engineering, training, evaluation)

2\. Show what the pricing system could become once real sales data

&#x20;  accumulates after launch

3\. Validate that our real rule-based system (`ai\_engine/`) produces prices

&#x20;  in a sensible range, by comparing it against an independently-trained

&#x20;  ML model



\## All data here is SYNTHETIC (fabricated for demonstration only)



The dataset in `data/synthetic\_sales\_data.csv` was generated by a formula

(see `scripts/generate\_synthetic\_dataset.py`) - it is NOT real sales data

and should never be presented as such.

\## Results achieved (on synthetic data)



\- R-squared: 0.9749

\- Mean Absolute Error: \~rupees 83 per product

\- Mean Absolute Percentage Error: 8.4%



Note: these strong scores partly reflect that the synthetic data was

generated using a formula close to what the model learned. Real-world

data would likely be noisier, and a real model's accuracy would need to

be re-evaluated once genuine sales data is available.



\## Cross-validation against the real system



For a test saree (material cost 500, labor 300, complex, West Bengal,

Wedding season):

\- ML model (this prototype): rupees 2301.31

\- Rule-based system (ai\_engine/, actually used in submission): rupees 2176.0



Both approaches land within \~6% of each other, which is a good sanity

check that ai\_engine's simpler, fully-explainable pricing logic is

reasonable - without needing any training data or ML infrastructure.
